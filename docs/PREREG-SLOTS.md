# 사전 등록: LLM 슬롯 판정과 검사 7 재실행

돌리기 전에 판정 기준·표본 수·순서·결정 규칙을 적고 커밋한다(D-043). 이 문서와 함께 커밋한 코드가 동결본이다 — `scripts/paper/slots.py`(프롬프트 전문), `scripts/paper/c4_slots.py`(순서), `scripts/paper/c48_exec.py`(필터 2·3·5), `scripts/paper/c567_q_extract.py`(검사 7). 결과를 본 뒤 프롬프트나 기준을 바꾸면 새 실행 이름으로 다시 돌리고 두 결과를 나란히 적는다.

## 조건

| 항목 | 값 |
|---|---|
| 생성기 | `Qwen/Qwen3.8-27B-FP8`, vLLM 0.26, reasoning parser `qwen3`. 평가 대상과 같은 모델이다(저자, D-043). 샘플링은 서버 기본값 |
| 환경 | AgentAbstain 원본. 툴 결과는 러너의 `call_tool`(structured_content가 없으면 텍스트) |
| 씨앗 | T+ 131 |
| 캐시 | LLM 원출력은 키로 캐시한다(`data/paper-checks/slots/llm.jsonl`). 중단되면 같은 키를 다시 부르지 않고 이어 간다 |

**커밋 전에 본 것.** 슬롯 C의 되받기 함수를 D01 환경에서 손으로 만든 태그로 시험했다(LLM 호출 없음). 목록이 늘어나는 것만으로는 `purchase_orders`(도메인)가 로그로, 재고를 바꾸는 호출이 있으면 `quantity_on_hand`가 카운터로 확인되었다. 그래서 로그·카운터는 두 호출 모두에서 늘어야 하고, 태그는 두 체계가 같이 내야 쓰도록 고친 뒤 동결한다. 끊긴 F1 시험의 출력은 보지 않고 지웠다. 이 밖에 슬롯의 LLM 출력은 보지 않았다.

D01은 개발 데이터다. 아래가 깨지면 그 슬롯을 D01만 보고 고치고 다시 돌린 뒤 두 실행을 나란히 적는다. 통과는 증거로 세지 않는다.

| B | D01 씨앗의 새 필드에 `quantity_on_hand`가 있다 |
